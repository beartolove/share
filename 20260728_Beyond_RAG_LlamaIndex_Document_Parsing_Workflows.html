Beyond RAG：瓶頸不在模型，而在文件解析

建立時間：2026-07-28 23:37:15（Asia/Taipei）

引用來源：Facebook 貼文｜全文 Blog｜原文投影片｜Jerry Liu 分享推文｜LiteParse｜ParseBench 論文

#科技及AI新知#RAG#LlamaIndex#文件解析#AI工程

重點摘要

  • 這份 LlamaIndex 工作坊把 RAG 的瓶頸往上游推：問題常不在模型，也不只在檢索，而是在文件解析時就把結構丟掉了。
  • 複雜 PDF 的 parsing 雖然在 12 個 RAG 痛點中只是一項，卻會連帶污染檢索、排序與合成，最後看起來像模型答錯。
  • 投影片建議把時間花在解析、chunking、檢索與 reranking；Cross-encoder reranking 是單一改動 ROI 最高的技巧之一。
  • CRAG 與 agentic loop 讓系統在生成前先判斷檢索品質：夠好就合成，不夠就改寫 query 或換來源。
  • LiteParse、LlamaParse 與 ParseBench 的共同訊息是：RAG 系統要能保留結構、量測改善，否則仍停留在 demo。

架構整理

主題重點
瓶頸移動從模型 → 檢索 → parsing → 文件結構；越上游錯，越難在下游修好。
Parsing 六種壞法多欄混合、表格斷裂、註腳內嵌、圖表消失、頁首頁尾污染、跨頁順序斷掉。
ROI 優先順序先 cross-encoder reranking，再 CRAG / Agentic Loop；大多團隊只需要 1–3 個技巧。
Long context 不是解藥成本、治理與可稽核性讓檢索仍然重要；retrieval 是 audit trail。
Eval 成熟化從 notebook 變成部署關卡：忠實度、相關性、召回率，分數掉了就擋。

可以怎麼解讀？

這份材料最有價值的地方，是把 RAG 優化的力氣重新定位：不要一開始就換模型或狂調 prompt，而是先檢查文件解析是否保留了表格、圖表、註腳、閱讀順序與 spatial text。只要上游結構壞掉，下游模型再強也只是在錯資料上生成。

可轉貼短文

這份 LlamaIndex 工作坊的重點不是再推一個 RAG 小技巧，而是提醒：RAG 的瓶頸已經往上游移動。若 PDF 表格、註腳、圖表與閱讀順序在 parsing 階段就壞掉，後面換模型、改 prompt、調 chunk size 都只是在錯的文字上做功。真正該做的是先檢查文件解析，保留 spatial text 與結構，再用 reranking、agentic loop 與 eval gate 管住整條 pipeline。

原文整理

📌 LlamaIndex 在 AI Engineer Singapore 2026 帶了一場 90 分鐘的工作坊《Beyond RAG: Building Agentic Document Workflows》，投影片 116 頁，由共同創辦人 Jerry Liu 在 X 上公開。

核心論點：瓶頸是檢索，不是生成；檢索裡面，瓶頸是 parsing；parsing 裡面，瓶頸是文件結構被丟掉。

RAG 流程是：解析文件 → 切成 chunk → 建索引 → 檢索 → 排序 → 交給模型生成。大部分調校花在模型，但真正改善常在更前面。

Parsing 只佔 12 個痛點裡的 1 個，卻會讓其中 7 個跟著壞。表格被解析成一行文字時，模型可能拿到對的頁，卻讀錯欄。

投影片建議一週時間分配：2 天解析與 chunking、2 天檢索與 reranking、1 天合成 prompt、0 天模型；而多數團隊實際上把時間花在 prompt 與換模型。

ROI 排序：第一名 cross-encoder reranking；第二名 CRAG 與 agentic loop；再來是多模態 caption-and-index、結構化資料走 JQ / SQL。HyDE 與 multi-query 則逐漸被 agentic loop 吸收。

CRAG 之後，Adaptive-RAG 用分類器先路由，Speculative RAG 用小模型平行草稿、大模型驗證，Search-R1 / R1-Searcher 則把搜尋動作放進模型推理裡。

Long context 沒有取代 retrieval，因為成本、權限治理與可稽核性仍讓檢索必要。Eval 也從 notebook 變成部署關卡：從 production query 抽樣，評忠實度、相關性與召回率。

Parsing 的六種壞法：多欄合併、表格碎片化、註腳混進本文、圖表跳過、頁首頁尾污染、跨頁閱讀順序斷掉。

Spatial text 是核心概念：PDF 不是一串文字，而是在 2D 畫布上有座標的 token。保留 x/y/寬/高/字體/樣式後，下游才有機會按列、欄、區域、bounding box 進行推理。

LiteParse 是 LlamaIndex 開源實作，Apache 2.0、本機執行、不需要雲端也不需要 LLM，內建 OCR。ParseBench 則以約 2000 頁人工驗證企業文件，評估 tables、charts、content faithfulness、semantic formatting、visual grounding 等能力。

星期一可以做的事：挑一種目前 pipeline 處理不好的文件型別，丟進 LlamaParse 或 LiteParse，比對現有 parser 的輸出，找出一個漏掉的具體結構。能量測一個改動有沒有幫助，才是系統，不然只是 demo。
