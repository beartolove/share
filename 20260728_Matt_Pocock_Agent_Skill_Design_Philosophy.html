重點摘要

  1. Skill 的目的：從隨機系統中逼出可預測流程；不是結果一樣，而是流程穩定。
  2. Trigger：model-invoked 省腦力但吃 context；user-invoked 零 context load，但增加人的記憶負擔。
  3. Structure：skill 由 steps 與 references 組成；是否拆外部檔案，看 branch，不只看長度。
  4. Steering：用 leading word、明確完成標準與正面描述，引導 agent 行為。
  5. Pruning：刪掉 no-op、duplication、sediment、sprawl；每一行都要能改變 agent 行為。

四個檢查表

檢查問題判準
Trigger誰叫得起來？自動觸發與手動觸發的成本不同。
Structure內容怎麼排？共用流程留本體，分支資訊推 reference。
Steering怎麼讓它照做？強術語與完成標準比空泛提醒有效。
Pruning什麼該刪？不改變行為的文字就是負擔。

對 Hermes Skill 的啟發

  • description 要用使用者真的會說的觸發詞。
  • 步驟應結束在可檢查的完成標準。
  • 避免「要徹底」「要清楚」這類 no-op 句子。
  • 長 reference 依情境分檔，並把 pointer 寫得更明確。

可轉貼短文

Matt Pocock 的 skill 設計哲學提醒我們：缺的不是更多 skill，而是一套判斷 skill 好壞的共用標準。好的 skill 不是把所有提醒塞進文件，而是讓 agent 每次穩定走同樣流程；每一行都必須真的改變 agent 行為。
