MCP 2026 更新：Stateless、Apps、Tasks 與企業級 Agent 標準

建立時間：2026-07-29 20:41:27（Asia/Taipei）

引用來源：Facebook 貼文 ｜ 官方來源網址：https://claude.com/blog/bringing-mcp-2026-07-28-to-claude ｜ MCP 2026-07-28 規格

重點摘要

  • Anthropic 宣布支援 MCP 2026-07-28 規格，核心方向是把 MCP 從偏 stateful 的連線模式，推向更容易部署與擴充的 stateless request/response 架構。
  • Stateless core 讓 MCP Server 更像一般 Web API，可部署在 serverless、edge 或標準 HTTP 基礎設施，降低 session、sticky connection 與斷線恢復的複雜度。
  • 長時間工作不再硬撐單一連線，而是交給 Tasks：先建立任務、取得任務 ID，再查進度、拿結果或處理失敗。
  • MCP Apps 讓工具不只回傳文字或 JSON，而是能在 Claude 對話中呈現互動 UI，例如按鈕、表格、表單、圖表與操作介面。
  • OAuth 2.0／OIDC、企業身分系統與 Tunnels 的補齊，代表 MCP 正從本機開發者工具，逐步走向企業級 AI Agent 連接標準。

這次更新的 5 個模組

Stateless Core

做什麼MCP Server 不必維持每條連線狀態；每次請求帶齊需要資訊，處理完就回傳。

意義讓 MCP 更容易部署到 serverless、edge 與一般雲端平台。

MCP Apps

做什麼工具可在 Claude 視窗裡顯示互動 UI，例如按鈕、表格、表單與圖表。

意義讓 Claude 從聊天機器人更像工作流程入口。

Tasks

做什麼長時間工作以任務 ID 追蹤，背景執行後再查進度與結果。

意義避免一條 HTTP 連線硬撐數十分鐘。

OAuth / OIDC

做什麼對接 Entra、Okta 或企業既有帳號與權限系統。

意義方便用部門、角色與離職停權管理 MCP 工具權限。

Tunnels

做什麼內部服務主動建立安全通道，Claude 透過通道呼叫內部工具。

意義降低內部系統直接曝露到公網的風險。

對開發者與企業的意義

開發者角度

  • 寫 MCP Server 會越來越像寫一般 Web API。
  • 可以少處理 session、sticky connection、斷線恢復與狀態同步。
  • 更容易把 MCP Server 部署到 Cloudflare Workers、AWS Lambda、Netlify 或一般雲端平台。
  • 長任務與互動 UI 被拆到 extensions，核心協定反而更簡單。

企業角度

  • MCP 開始具備企業正式上線需要的身分驗證、權限控管、內網連線與監控基礎。
  • 可用既有企業帳號體系控管部門權限，不必為 MCP 另建帳號。
  • 內部資料庫、ERP、製造系統或私有 API 可透過 Tunnels 連接，降低資安阻力。
  • MCP 正在從「開發者本機工具」走向「AI Agent 連接企業系統的共同標準」。

https://www.facebook.com/share/1EbGUvPtMB/ MCP 標準重大革命，大家都向輕量、Agent 靠攏 MCP 迎來重大革新！最重要的就是 - 狀態變成 Statelsss - MCP Apps 功能 - 加入 OAuth 認證 - 加入 Tasks 功能 - 加入 Tunnels 功能 這次最核心的改變，是 MCP 底層設計改成 Stateless，也就是「伺服器不用一直記住你前面做過什麼」。以前的做法比較像打電話給客服，電話接通之後，客服會記得你剛才講過哪些內容，整段連線也必須持續維持。如果連線中斷、伺服器重啟，或流量被分到另一台機器，就可能要處理一堆 session、狀態同步和斷線恢復的問題。新版則更像一般網站 API，每次 Claude 發出請求時，都把這次需要的資訊一起帶過去，伺服器處理完就回傳，不需要一直維持一條專屬連線。 這個改變最重要的地方，就是它直接影響 MCP Server 能不能真正大量部署。當伺服器不用記住每一個連線狀態，就可以部署到 AWS Lambda、Cloudflare Workers、Serverless 或一般雲端平台上。使用者從一百人增加到十萬人時，可以直接多開幾台機器分攤流量，不必擔心某個使用者上一個請求在哪一台伺服器，下一個請求是不是又必須回到同一台。對企業來說，這代表 MCP 不再只是開發者在本機玩玩的小工具，而是開始具備正式上線需要的擴充能力。 Stateless 並不代表 Claude 失去記憶，也不代表 Agent 每做一步就忘記前面發生什麼。MCP 最底層的通訊協定不再強迫伺服器維持 session。真正需要長時間執行的工作，例如分析一萬份文件、跑一個需要四十分鐘的資料流程、建立完整專案並測試，會交給新的 Tasks 機制。Claude 先送出工作，伺服器回覆一個任務編號，接著在後台慢慢執行，Claude 之後再查進度、拿結果，或確認任務是否失敗，這樣就不用讓一個 HTTP 連線硬撐幾十分鐘。 另一個重點是 MCP Apps。以前 Claude 呼叫一個工具，通常只會拿回文字、JSON 或一些資料，使用者真正要操作時，還是得切換到外部網站。MCP Apps 想做的，是讓工具可以直接在 Claude 的對話視窗裡顯示按鈕、表格、表單、圖表或其他互動畫面。例如 Claude 連到 Figma 之後，不只是回覆「設計已建立」，而是可以直接把設計結果或操作介面顯示在聊天裡。這會讓 Claude 從單純的聊天機器人，慢慢變成一個可以直接操作各種軟體和工作流程的入口。 企業最在意的登入和權限問題，這次也開始補齊。新版 MCP 對 OAuth 2.0 和 OIDC 的支援更完整，直接接 Microsoft Entra ID、Okta 或公司原本的帳號系統。企業不用另外為 MCP 建一套帳號，也不用讓每個員工手動授權。可以直接規定財務部能使用會計系統，工程部能使用 GitHub 和部署工具，一般員工不能執行管理員操作。員工離職後，只要停用公司帳號，對應的 MCP 權限也會一起失效，整體管理方式會比較接近現在成熟的企業 SaaS。 安全呢？用 Tunnels 解決。公司的內部系統無法上公網，例如內部資料庫、ERP、製造系統或私有 API，但 Claude 如果要使用它們，就必須有一條安全的連線方式。MCP Tunnels 的概念，是讓公司內部的服務主動建立一條安全通道出去，Claude 再透過這條通道呼叫內部工具。這樣公司不需要把內部系統直接暴露在網路上，也不需要為了 Claude 特別開防火牆入口，對資安部門來說會比較容易接受。 所以這次 MCP 更新真正重要的地方，不是多了幾個新功能，而是 Anthropic 正在重新整理整套架構。簡單、快速的工具呼叫，就走普通的 Stateless API。需要跑很久的工作，就交給 Tasks。需要互動畫面，就用 MCP Apps。登入和權限，直接接企業原本的身分系統。內部網路連線，則透過 MCP Tunnels 處理。每一個功能都拆開處理，核心反而變得比較簡單，整套系統也更容易維護。 從開發者角度來看，未來寫 MCP Server 會越來越像寫一般 Web API，不需要一直煩惱 session、sticky connection、斷線恢復和狀態同步。從企業角度來看，MCP 也開始補上權限控管、身分驗證、內網連線和監控這些正式上線一定會遇到的問題。這代表 MCP 正在從一個很有趣的開發者協定，慢慢走向 AI Agent 連接外部工具和企業系統的共同標準。 參考網址： https://claude.com/blog/bringing-mcp-2026-07-28-to-claude
