重點摘要

  1. Agent 和聊天 AI 的差別在於能不能完成任務。 聊天 AI 像顧問，主要回答問題；Agent 則會根據目標拆解步驟，使用瀏覽器、終端機、檔案與工具把事情做完。
  2. 使用 Agent 要給清楚的目標、權限與驗收標準。 不只是要求產生一段文字，而是要讓它知道要完成什麼、能動哪些資源、最後怎麼驗收。
  3. 三種平台可以理解成三種工作台。 ChatGPT 適合討論、整理文字與規劃；Codex／GPT Work 偏向程式與檔案任務；Gemini Antigravity 則是這次示範的 Agent 工作環境。
  4. Skill 的本質是把可重複流程包成可安裝、可呼叫的能力。 Skill 內通常會定義角色、流程、輸出規格、檔案格式與相依項，讓 Agent 不必每次重新理解同一套做法。
  5. 實作時要注意專案目錄、全域／專案安裝與相依性。 有些 Skill 不是單一檔案，會引用其他 Skill 或規格檔；建議透過安裝流程處理，不要只手動複製資料夾。
  6. Skill 變多後，命名、分類與搜尋很重要。 可用斜線或前綴分類，例如簡報、檔案、檢核表等；也可用檔案搜尋工具輔助找到本機 Skill。

關鍵觀察

  • AI Agent 的價值在於「任務導向」，不是只比誰回答得漂亮。
  • Skill 是讓 Agent 變穩定的關鍵：把經驗、流程與標準保存下來。
  • 企業或團隊導入 Agent 時，不能只教 prompt，更要建立可重複、可驗證的工作流程。
  • 安裝別人的 Skill 要留意相依性與安全，不建議只複製貼上。
  • 當 Agent 逐漸懂得「一頁圖、兩頁圖、share」等慣用語，團隊可以把高頻工作變成自己的技能庫。

適合使用情境／可延伸思考

  1. 先盤點資訊處常做的高頻任務：簡報、會議整理、檔案轉換、檢核表、系統說明與知識分享。
  2. 把每個高頻任務整理成 Skill：觸發條件、輸入資料、步驟、輸出格式、驗證方式與常見錯誤。
  3. Skill 命名要能搜尋與分類，例如 slide-*、share-*、meeting-*、checklist-*。
  4. 先在專案目錄或沙箱測試外部 Skill，確認相依性與行為後再放到共用環境。
  5. 逐步把「會問 AI」升級成「會管理 Agent 工作流」，讓團隊累積可重用能力。

5 頁摘要圖內容規劃

  1. 1/5：AI 正從聊天顧問變成任務型 Agent。
  2. 2/5：三種 AI 工作台：ChatGPT、Codex、Gemini Antigravity。
  3. 3/5：Skill 是 Agent 的可重複能力包。
  4. 4/5：實作 Skill 要注意專案、相依性與驗收。
  5. 5/5：團隊導入 Agent 的下一步：建立自己的 Skill 庫。
