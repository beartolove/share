NVIDIA Nemotron 3.5 ASR Streaming：40 語言即時語音辨識模型開源

NVIDIA 釋出多語串流 ASR 模型，主打低延遲、高並發與語音 Agent 場景。

#科技及AI新知#ASR#語音Agent#NVIDIA#開源模型

官方來源網址：https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b

重點摘要

  • NVIDIA 釋出 Nemotron-3.5-ASR-Streaming，是 600M 參數的多語即時語音辨識模型，主打 40 種 language-locales。
  • 模型採用 Cache-Aware FastConformer-RNNT 架構，支援串流與批次 ASR，並內建標點與大小寫處理。
  • 延遲可依 chunk size 調整，圖中列出 80ms、160ms、320ms、560ms、1.12s 等設定，適合在低延遲與吞吐量間取捨。
  • 官方資料與圖表顯示，單張 H100 可依 chunk size 支援約 240～2400 條並行串流，對語音 Agent 與即時語音應用很關鍵。
  • 對開發者與企業而言，這代表可把串流 ASR 從外部 API 依賴，往自架、可控延遲與高並發部署推進。

關鍵規格

模型nvidia/nemotron-3.5-asr-streaming-0.6b
參數量600M
語言支援40 language-locales
架構FastConformer Cache-Aware RNN-T / RNNT with prompt
Chunk size80ms、160ms、320ms、560ms、1.12s
輸出能力轉錄文字、標點、大小寫、自動語言標籤
授權OpenMDW-1.1；Hugging Face 頁面標示可商用

為什麼值得注意？

低延遲與高並發一直是語音 Agent、會議即時字幕、客服語音機器人、通話分析與邊緣語音應用的瓶頸。Nemotron 3.5 ASR 把多語、串流、標點、語言偵測與高吞吐部署整合在同一個開源模型方向上。

導入時要看的取捨

chunk 越短通常越接近即時互動需求，但吞吐、穩定性與準確率可能要一起評估；chunk 越長可支援更多並發串流，但互動延遲也會提高。實際上線仍要用自己的語音資料、口音、噪音與領域詞彙測試。

適合應用

語音 Agent、即時字幕、會議轉錄、客服通話分析、車載或邊緣語音介面、需要自架與資料治理的企業語音工作流。
