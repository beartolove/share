AI 改 code 一直改 A 壞 B？你缺的是這五個步驟

官方來源網址：https://youtu.be/CMs8YMU6_RM

重點摘要

  • 用 AI 維護既有專案時，問題常不是模型不夠強，而是沒有先讓 AI 理解 Brownfield 專案脈絡。
  • Greenfield 是空地蓋新房；Brownfield 是在已有人使用的房子裡改管線，不能只靠「直接改」。
  • 進入陌生 codebase 時，應先讓 AI 找入口、畫資料流、標出相依關係與可能影響範圍。
  • 修改前要設定保護欄：小步改、列受影響檔案、補測試或手動驗證，並確認舊功能沒壞。
  • 從 Vibe Coding 升級到 Agentic Engineering 的關鍵，是 shared context、harness、測試與可驗證交付。

適合情境

side project 前期很順、後期互相改壞；或工程師接手公司既有專案，想用 AI 安全理解與維護。

導入提醒

不要把 Brownfield 當 Greenfield 操作；AI 改 code 前，先要求它理解脈絡、列風險、提出驗證計畫。
