anydoc：把辦公檔案快速轉成乾淨 Markdown

Firecrawl 開源的 anydoc，把多種辦公檔案轉成一致、乾淨、適合 AI 工作流使用的 Markdown。

重點摘要

  • anydoc 是 Firecrawl 開源的 Rust 檔案轉 Markdown 工具，目標是把多種辦公格式轉成乾淨的 GitHub-Flavored Markdown。
  • 它把不同格式先解析進共同資料模型，再由單一 Markdown 序列化器輸出，因此表格、清單、註腳等結構能維持一致處理。
  • 官方 README／blog 指出支援 Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV 與文字型 PDF 等格式，且包含 Node.js、Python、WASM、CLI 與 Agent Skill 用法。
  • 效能主打本機、純 Rust、不載入 ML 模型、不呼叫外部服務；官方 benchmark 宣稱中位轉換時間低於 5 ms。
  • 限制上，anydoc 適合可讀文字與結構化內容；掃描頁或照片型 PDF 仍需要 OCR／視覺流程輔助。

小河提醒：官方 benchmark 很亮眼，但導入時仍要用自己的檔案樣本驗證表格、註腳、投影片備註與掃描頁處理品質。

怎麼運作

  1. 先判斷檔案內容標記，不只依賴副檔名。
  2. 不同格式進入共同資料模型。
  3. 再由同一個 Markdown 序列化器輸出。
  4. 文字型 PDF 可在本機處理；掃描頁仍需 OCR 或視覺模型。

適合使用情境

  • 把歷史 Office 檔案整理成知識庫。
  • RAG 前處理、搜尋索引、摘要與問答工作流。
  • Agent 需要讀取使用者上傳的混合格式檔案。
  • 希望轉換流程本機執行，不把檔案送到外部服務。

原文整理

快速把任何辦公檔案轉成乾淨的 Markdown？！

Firecrawl 開源 anydoc，支援將 Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV、PDF 統一轉換成 GitHub-Flavored Markdown，連 .doc、.ppt、.xls 這類舊格式都在支援範圍內。

anydoc 會將所有格式都先解析進同一套資料模型，再由單一 Markdown 序列化器輸出，所以不論輸入是二十年前的 .doc 還是昨天做的 .pptx，表格、註腳、清單編號的處理都一致。另外格式判斷是讀檔案內容本身的標記，副檔名標錯的檔案照樣轉得出來。

效能是它的主打。純 Rust、不載入任何 ML 模型、不呼叫外部服務，中位轉換時間低於 5 毫秒。官方 benchmark 拿 100 份真實檔案、橫跨十四種格式，與另外六套轉換器對比，由 LLM 評審盲測比對 LibreOffice 渲染的原始頁面，結果 anydoc 是唯一覆蓋全部十四種格式的工具，每一種格式的品質分數都最高，速度也比次快的工具快一個量級。
