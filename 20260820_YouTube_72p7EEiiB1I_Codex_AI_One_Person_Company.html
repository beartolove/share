重點摘要

  • 這支影片示範 Codex 版「AI 一人公司」：先從一個能做事的 Agent 開始，再視任務複雜度擴成團隊。
  • Chat 像顧問，Work 像執行助理，Codex 則更像能讀寫本機檔案、呼叫命令列工具的工程師。
  • 若任務只是整理檔案、寫報告、每週產出資料，一個 Agent 通常已經足夠。
  • 當開始需要 vibe coding、小工具開發、程式碼審查與拍板，就可以拆成 CEO、代代、查查三角色。
  • 真正關鍵不是單句 prompt，而是設計 loop：需求、實作、審查、返工、驗收與安全標準。
  • AI 能自己迭代很多輪，但產品品味、取捨、是否上架，最後仍需要人判斷。

一句話總結

AI 一人公司的起點不是「多找幾個 AI 員工」，而是先把一個真實任務交給 Codex Agent，再逐步設計可驗收、可返工、可保護隱私的工作循環。

實作架構

層次重點
先用一個 Agent從整理檔案、寫報告、讀取財報、連接 Obsidian 等低風險任務開始。
再拆三角色CEO 統籌規劃，代代寫程式碼，查查審查與要求返工。
設計 loop讓 Agent 自己實作、審查、修正、驗收，而不是人一直盯著。
保留人類判斷功能是否順手、畫面是否好看、要不要上架，仍由人把關。

導入提醒

  • 不要一開始就追求整套 AI 公司；先找到一件真實又重複的工作來測。
  • 驗收標準要寫清楚，特別是「能用」與「不暴露隱私／密鑰」。
  • 專案一多要注意 token 消耗與成本，不要讓 Agent 無限迭代。
  • skill 可以強化角色，但品味、取捨與商業判斷仍然是人的責任。
