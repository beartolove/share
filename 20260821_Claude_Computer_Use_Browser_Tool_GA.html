Claude Computer use 與 Browser tool 正式版：企業 UI 自動化的新拼圖

Anthropic 將 Computer use、Browser tool、Files API、Skills API 從 beta 推向正式版。對企業來說，重點不是「AI 會點滑鼠」而已，而是大量沒有 API 的後台與網頁流程，開始可以用更標準化的 agent 工具組來處理。

ClaudeComputer useBrowser toolSkills API企業自動化

重點摘要

  • 四個能力正式化：Computer use、Browser tool、Files API、Skills API 從 beta 轉正式版，舊 beta 串接遷移期間仍可用。
  • Computer use 適合沒有 API 的桌面／後台流程：Claude 看截圖、回傳滑鼠鍵盤動作，開發端在自己的環境執行。
  • Browser tool 是新重點：它讀網頁無障礙樹與元素引用，不靠座標；網頁任務應優先考慮 Browser tool，結構不穩再退回 Computer use。
  • 上線難點在縮放、座標與成本：新版要求開發端自行控制截圖尺寸與座標換算，工具定義與截圖也都會消耗 input tokens。
  • 風險不能省略：Prompt injection、帳密、金錢或同意條款等有後果動作，需要隔離環境、白名單網路與人工確認。

能力比較

能力核心用途適合場景注意事項
Computer use看截圖、回傳座標與鍵盤滑鼠動作桌面應用、沒有 API 的後台、跨系統 UI 操作要自行縮放截圖與換算座標；Retina 螢幕特別容易偏移。
Browser tool讀網頁元素結構與無障礙樹網頁表單、頁面讀取、分頁管理、元素操作目前只在 Claude API；動態頁或虛擬捲動可能需要退回截圖座標。
Files API檔案進出請求流程理賠 PDF、確認單、下一輪請求的中間檔新增 file expiration，可設定檔案到期時間。
Skills API把 SOP 版本化掛到請求企業作業流程、claims-filing v3、可控流程版本每次請求可指定 SOP 版本，便於治理與回溯。

成本與工程提醒

先算工具定義，再算截圖。貼文整理指出，computer toolset 約 4,500 input tokens、browser toolset 約 6,600 input tokens；每張截圖約 1,000～1,800 input tokens。十幾步任務如果每輪都帶圖，成本會很快累積。
  • 一次請求圖片盡量控制在 20 張內。
  • 只保留最近 3 張截圖，約每 25 輪分批清理。
  • 不要每輪刪一張圖，避免 prompt cache 一直失效。
  • cache_control 斷點放在 system prompt 與 tool definitions 之後。

上線前風險檢核

能自動化，不代表要全自動。Prompt injection 是 Computer use / Browser tool 類工具的核心風險，網頁文字、圖片與文件裡藏的指令都可能影響模型行為。
  • 使用權限最小的獨立 VM 或容器。
  • 網路只開白名單網域。
  • 不要直接把帳號密碼交給 agent；必要時以受控方式提供。
  • 金錢、條款、Cookie、發文、刪除等有後果動作保留人工確認。
  • 讓終端使用者知道風險並取得同意。
  • 截圖、輸入與過程檔案保留在使用方環境，有助於符合 ZDR 資格。

原文整理

Claude 的 Computer use tool轉成正式版，Anthropic 這次一口氣把四個功能從 beta 推上正式版，其中 Browser tool 是全新的，它不看螢幕座標，直接讀網頁的元素結構。企業裡實際運用場景，有非常多可能是沒有api的，大部分都是用介面ui來做工作流，所以電腦或瀏覽器操作還是企業中大部分看到的場景，所以computer use相關的api會是一個值得關注的功能

Anthropic 官方 ClaudeDevs 發的一支一分鐘影片，加上 Claude Platform 上 computer use 與 browser tool 的技術文件。影片講的是四個東西同時從 beta 轉成正式版：Computer use、Browser tool、Files API、Skills API，同樣的定價、同樣的模型，舊的 beta 串接在遷移期間繼續能用。

━━━━━━━━━━━━━━━━━━━━
▍先講 computer use 是什麼

想像一個遠端同事，他看不到公司的資料庫，也沒有任何後台權限，能給他的只有一張螢幕截圖，他能還回來的只有滑鼠移到哪裡、點哪裡、鍵盤打什麼。Computer use 就是這件事，Claude 看截圖，回傳座標跟按鍵，開發端的程式去執行，執行完再截一張圖給它看。

這跟串 API 是兩條不同的路。串 API 的前提是對方有 API，而且要有權限、有文件、有工程時間去接。Computer use 走的是人類本來就在走的那條路，只要一個人能用滑鼠鍵盤把事情做完，它也可以。

官方影片示範的情境是一個叫 Meridian 的保險理賠後台，畫面上是理賠編號、金額、保戶姓名，還有 Reject 跟 Approve 兩顆按鈕，隊列裡有 14 件待處理。字幕寫的是「Automate work in applications that have no API, in production」，重點落在 in production 那幾個字。

━━━━━━━━━━━━━━━━━━━━
▍最有感的改動：一輪可以做好幾個動作

以前的模式是一個動作一次來回。點一下要問一次模型，打字要再問一次，按 Enter 再一次，截圖確認再一次，光是填一個欄位就四趟來回，每一趟都要付完整的網路延遲加上模型推理時間。

新的 computer_toolset_20260801 可以在同一輪回傳好幾個 tool_use 區塊，點擊、打字、按鍵、截圖一次給完，執行端照順序跑完，再把所有結果一起回傳。影片那張圖直接把「4 round trips」跟新版的單一批次並排，差距很明顯。

執行的規則有一條要注意，這些動作必須照它給的順序跑，中間有任何一個失敗，後面的全部不要跑，回傳的時候在被跳過的動作上標註「Not executed: an earlier computer action in this turn failed.」，讓模型知道發生什麼事。這條沒做對的話，畫面狀態會跟模型腦中的狀態對不起來。

━━━━━━━━━━━━━━━━━━━━
▍新的動作有哪些

正式版總共有 17 個動作。滑鼠那一類除了原本的左中右鍵、雙擊、拖曳，多了 triple_click（三擊選整行），也把 left_mouse_down 跟 left_mouse_up 拆開來用，處理比較複雜的拖曳。鍵盤那邊 key 動作現在可以帶 repeat 參數，一到一百次，連按十次向下鍵不用送十個動作。

比較實用的是新增的三個。zoom 給一個矩形區域，它會把那塊用原始解析度截回來，用途是讀小字，因為完整截圖為了塞進圖片限制通常會被縮小，縮小之後密集的 UI 或小字就糊掉了。wait 讓它單純等幾秒，等應用程式載入，上限 300 秒。hold_key 是按住某個鍵不放一段時間。

zoom 預設是開的，環境做不出區域截圖的話可以在 configs 裡關掉，關掉還能省大約 410 個 input token。

━━━━━━━━━━━━━━━━━━━━
▍截圖現在要自己縮放，這是最容易出錯的地方

舊版只要告訴 API 螢幕多大，它會幫忙處理。新版不幫了，文件寫得很明白，回傳的截圖必須已經符合模型的圖片尺寸限制，超過就直接被驗證錯誤擋下來。

新一代模型（Opus 4.7 之後、Fable 5、Mythos 5、Opus 5、Sonnet 5）的限制是長邊 2576 px，總量 4784 個 visual token，大約 3.75 百萬像素。舊模型是長邊 1568 px、約 1.15 百萬像素。視覺 token 的算法是寬除以 28 無條件進位，乘上高除以 28 無條件進位。

縮放之後還有第二件事，Claude 回來的座標落在「送出去的那張截圖」的像素空間，要按同樣的比例換算回真實螢幕座標才去點。zoom 也不改變這件事，放大之後它給的座標仍然是完整截圖的座標系。

macOS 的 Retina 螢幕是另一個需要注意的細節，截圖的像素是邏輯座標的兩倍，處理方式是先把圖縮一半，或者把 Claude 給的座標除以二。兩個都沒做的話，滑鼠會固定偏到右下角，而且偏得很有規律。

解析度的建議值，文件給的基準線是 1280x720，一般桌面任務 1024x768 或 1280x720，網頁應用 1280x800 或 1366x768，超過 1920x1080 就不建議了。點擊一直不準的時候，先回頭檢查解析度跟座標換算，那通常是原因。

━━━━━━━━━━━━━━━━━━━━
▍Browser tool：讀網頁結構，不讀座標

這是整段公告裡技術含量最高的一塊。同一個理賠畫面，browser_toolset_20260801 讀的是頁面的無障礙樹，做過網頁自動化的人應該有經驗，座標式的自動化最常死在版面一動就全錯。

Browser tool 預設帶 27 個動作，加上選用的總共 31 個。讀取那一組是 read_page（拿無障礙樹跟元素引用）、find（用自然語言找元素）、get_page_text（純文字）。表單有 form_input 可以直接塞值。分頁管理有 new_tab、list_tabs、switch_tab、close_tab。

有四個預設關閉的，javascript_exec、read_console、read_network、file_upload，這幾個風險比較高，需要才開。

兩個限制要知道。第一，browser tool 目前只在 Claude API 上有，Claude Managed Agents 裡面沒有。第二，元素引用是盡力而為，遇到高度動態或虛擬捲動的頁面還是可能掉，這種時候就退回截圖加座標那條路。

Toolset 本身的成本大約 6,600 個 input token，四個選用動作全開再加 880。

━━━━━━━━━━━━━━━━━━━━
▍四個零件組成一個 agent

影片中間有一張圖叫「Four pieces of one agent」，畫的是一次 POST /v1/messages 裡面塞了三種東西：files 放進 intake_2024-88412.pdf，skills 掛上 claims-filing 的 v3，tools 掛上 computer_toolset_20260801 跟 browser_toolset_20260801。

字幕解釋 skills 的定位是「your procedure, versioned」，你的作業流程，有版本，每次請求掛上去。這跟 Claude Code 或 Cowork 裡面寫的 Skill 是同一個概念，只是搬到 API層，可以在請求層決定這次要用哪一版的 SOP。

Files API 這次多了 file expiration，可以設定檔案的過期時間。影片最後那張是產出的 confirmation_88412.pdf 帶著 file id，字幕寫「The confirmation comes back as a file, retrieve it, or route it into the next request」，檔案進去、檔案出來，中間不用經過自己的儲存空間。

還有一張灰字的過場：「Files and Skills are the primitives behind Claude Managed Agents」，意思是這兩個東西本來就在 Managed Agents 底下跑，現在把它們單獨開放出來給開發者自己組。

━━━━━━━━━━━━━━━━━━━━
▍成本要先算清楚

根據官方文件，computer_toolset_20260801 光是工具定義本身就要大約 4,500 個 input token，Opus 5、Opus 4.8、Fable 5、Mythos 5 大約 4,520，Sonnet 5 大約 4,590。Browser toolset 大約 6,600。這是每一次請求都要付的。

然後是截圖，每張大約 1,000 到 1,800 個 input token，按圖片計價。一個十幾步的任務跑下來，截圖的量會很可觀。

文件給的省法有幾個。一次請求裡的圖片保持在 20 張以內，超過 20 有比較嚴的限制。只留最後三張截圖，然後每 25 輪左右清一次，重點是分批清，不要每輪清一張，因為每輪都動會讓 prompt cache 一直失效。cache_control 的斷點放在系統提示加工具定義之後，剩下最多三個放在最近幾輪的最後一個 tool_result 上。

━━━━━━━━━━━━━━━━━━━━
▍缺點跟風險
Prompt injection 是這類工具最大的問題。文件的原話是，在某些情況下 Claude 會照著它在畫面內容裡看到的指令做，即使那跟開發者的指令衝突，網頁上的文字或圖片裡藏的指令都可能蓋過原本的設定。

Anthropic 的做法是模型本身有針對這件事訓練過，另外加了一層分類器，只要在截圖裡偵測到疑似注入，就會自動導引模型停下來要求使用者確認才繼續。這層是預設開的，要關掉得聯絡官方。

他們建議的防護措施，用一台權限最小的獨立 VM 或容器來跑，網路只開白名單網域，不要把帳號密碼交給它，真的必要的話用 XML 標籤包起來，牽涉到金錢、同意條款、接受 cookie 這類有後果的動作要求人工確認。還有一條容易被忽略的，要讓終端使用者知道風險並取得同意。

功能上的限制也一併說。延遲仍然比人手動操作慢，適合非即時的場景，例如背景收資料或自動化測試。座標還是會出錯甚至幻覺。捲動在某些應用程式裡會沒反應，文件直接建議改用 Page Down 這類鍵盤操作。試算表這種需要精細滑鼠控制的介面，複雜操作常常要試很多次。社群平台上開帳號、發內容的能力是刻意受限的。

有一件事對有法遵要求的企業客戶蠻重要，所有截圖、滑鼠鍵盤輸入、過程中的檔案都存在使用方自己的環境，不存在 Anthropic 那邊，所以 computer use 符合 ZDR（零資料保留）的資格。
