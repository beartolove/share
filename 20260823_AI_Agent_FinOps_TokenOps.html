AI Agent 的 FinOps：誰花掉了所有 Token？

這支 Microsoft 講者的分享，核心問題是：AI Agent 能自主做事，也代表它可能自主花錢。企業需要的不只是模型 Gateway 或硬上限，而是能在 Agent run 邊界上做成本歸因、記帳、政策與即時調整的 TokenOps 控制平面。

重點摘要

  • 問題：帳單看得到，但常追不到是哪個 Agent run、工具呼叫或迴圈造成成本。
  • 缺口：request-level gateway 可以限流或路由，但看不到整個 Agent 行為。
  • 解法：在邊界上加 instrumentation、ledger、policy 與 governor。
  • 治理方式：先 preview 觀察，再 steer 調整，最後才 halt 停止。
  • 企業提醒：FinOps 不是單純砍成本，而是讓每個 Token 都能對應到可追蹤的價值。

用 segment、ledger、budget、action、policy 決定何時觀察、調整或停止。

只執行開發者允許的 action，讓成本治理不會破壞 Agent 行為。

企業導入檢核

如果公司要讓 AI Agent 進正式工作流，不能只問「模型準不準」，也要問「成本能不能歸因、能不能預警、能不能先調整而不是直接中斷」。
  • 每個高成本工具呼叫是否有 boundary？
  • 是否能把成本歸因到使用者、Agent、run、工具或 cohort？
  • 是否有 preview mode 先觀察政策效果？
  • 是否優先使用 context compaction、tool output reduction、succinct response 等 steering？
  • 是否把 ledger 當成未來政策優化的資料來源？

一句話總結：
AI Agent 的成本治理不能只靠模型 Gateway 或硬性預算上限，而要在 Agent run、工具呼叫、上下文成長與迴圈行為的邊界上，建立可歸因、可記帳、可即時調整的 TokenOps 控制平面。

核心重點：
1. 從 Token maxing 轉向 value maxing：探索期大量消耗 Token 可以理解，但成熟期要能回答「誰花了 Token，帶來什麼價值」。
2. 成本發生在 LLM model call 邊界，但失控原因常在 Agent run 層：工具輸出太多、上下文膨脹、子 Agent 生成、runaway loop。
3. 只靠 request-level gateway 不夠：模型路由、硬上限與降級模型只能處理模型請求，無法看見整個 Agent 行為。
4. TokenOps 架構包含 instrumentation、accounting、enforcement：先觀測與歸因，再用 ledger 記帳，最後用 policy steering 或 halt 控制。
5. Boundary annotation 是關鍵：它記錄方法的輸入輸出，也讓控制平面能把 action 推回 Agent。
6. Governor 讓控制變安全：只有開發者允許的 action 才能被套用，避免控制平面任意改 Agent 行為。
7. Preview mode 可先觀察政策效果：正式上線前，可先看 guardrails 會如何觸發，再調整 threshold。
8. Steering 比單純 throttling 更有價值：不是超支就殺掉 Agent，而是先縮減輸出、壓縮上下文、注入節省預算的指令，盡量讓任務完成。

關鍵架構：
- Agent runtime：使用者自己的 Agent 工作流。
- Bridge：包含 attribution、boundary annotation、governor、wrap complete。
- Control Plane：包含 segment、ledger、budget、action、policy。
- Policy Catalog：涵蓋花費管理、上下文管理、工具輸出縮減、迴圈偵測、進度偵測。

Demo 重點：
1. Preview mode：政策會執行與記錄，但不真正阻擋或修改 Agent。
2. Halt mode：超過 per-run cost cap 時，Agent 被直接停止，像斷路器。
3. Steer mode：Cost Guard 根據預算消耗與 Token 消耗速度，預測是否會超支，並注入或套用調整讓 Agent 有機會完成。

可落地的企業提醒：
- 不要只看總帳單，要能追到「哪個 Agent run、哪個工具、哪個使用者或 cohort」。
- 對高成本工具呼叫加 boundary annotation。
- 先用 preview mode 累積資料，再啟用 halt 或 steer。
- 優先採用可恢復的 steering，例如 context compaction、tool output reduction、succinct response，而不是一開始就 kill。
- Ledger 不只是成本紀錄，也可以成為未來自動產生政策與調參的資料來源。
