什麼樣的 Agent 專案才能為履歷加分

這支影片提醒：能為履歷加分的 Agent 專案，不是單純呼叫模型 API 或包一個聊天框，而是能解決真實業務痛點、具備企業級架構、安全治理、可觀測性與量化成效的完整系統。

重點摘要

  • 不要只做聊天 demo：只包 API、寫 prompt、套對話框，無法證明工程能力。
  • 要解真實業務流程：Agent 要能跑完多步驟、跨工具、端到端的產業流程。
  • 多 Agent 要有必要性：只有業務真的複雜，才拆需求、程式碼、測試等角色。
  • 上下文要精準分發：不要塞滿聊天紀錄，只給當前任務最需要的資訊。
  • 記憶架構要分層：工作記憶、知識庫、外部狀態分開管理，降低成本與混亂。
  • 後端要能進生產：API、資料庫、併發隔離、權限控制與日誌追蹤都要到位。
  • 高風險節點要人工審核：查詢可自動，付款、刪除、敏感資料必須審核與二次確認。
  • 要有全鏈路可觀測：trace ID、節點流轉、工具輸入輸出與耗時都要能查。
  • 成效要能量化：任務成功率、回應耗時、QPS、token 成本與自癒率要可衡量。
  • 履歷要寫工程成果：用 STAR 與工程語言說清架構、風險控制、指標與業務價值。
