#科技及AI新知#MCP#Claude#企業治理

MCP Connector 企業集中授權｜管理員一次設定，全員自動連線

Enterprise-managed auth 讓企業把 MCP Connector 的授權從個別 OAuth，收斂到既有 IdP 與群組權限管理：管理員設定一次，使用者登入 Claude 後工具自動就位。

建立時間：2026-08-25 23:44:58（Asia/Taipei）

來源：Facebook 貼文｜ClaudeDevs X 公告｜Anthropic 官方部落格｜官方文件

重點摘要

企業集中授權 GA

MCP Connector 的 Enterprise-managed auth 已正式對 Claude Team / Enterprise 管理場景開放，目標是把多人的 Connector 授權從「每人逐一 OAuth」改成「管理員集中設定」。

使用者零步驟上線

管理員透過既有 IdP 授權一次，使用者登入 Claude 後即可繼承群組與角色權限，Connector 在 Claude Chat、Claude Code、Cowork 間保持一致。

治理回到 IdP

權限劃分、撤銷、token 有效期與工作／個人帳號分離，都回到組織原本的身份治理流程，不再把 MCP 變成另一個孤立的安全介面。

建立在開放標準

這是 MCP Enterprise-Managed Authorization extension 的實作方向；內部 custom connector、MCP 提供商與 IdP 都可依規格支援。

生態系已啟動

目前重點伙伴包含 Okta、Asana、Atlassian、Canva、Figma、Granola、Linear、Supabase、Slack、Datadog、Notion，以及 HubSpot、Ramp、Webflow 等企業客戶。

以前卡在哪裡？

  • 管理員先啟用 Connector，接著每位使用者還要自己跑一次 OAuth。
  • 人數一多，授權排隊、審核與支援工單會成為企業導入 AI 工具的摩擦。
  • Ramp 的案例提到：2,000 名員工透過 Okta 配置後，第一天登入 Claude 就已經連好工具。

現在怎麼運作？

  • 管理員把組織 IdP 接到 Claude，挑選要啟用的 MCP Connector。
  • 使用者登入後，透過 IdP 群組與角色繼承權限，不需要逐一授權。
  • 同一套權限會跨 Claude Chat、Claude Code、Cowork 生效。

管理員新增的控制力

  • 可以縮短 access token 有效期，降低撤權後舊 token 殘留風險。
  • 可透過 IdP 處理撤銷與群組授權，與其他 SaaS 工具管理流程一致。
  • 可要求 Connector 只能經由 IdP 連線，避免個人帳號誤連公司工具。

為什麼開放標準重要？

  • 不是只綁定單一廠商的私有做法，而是建立在 MCP 授權 extension。
  • 企業內部自建 connector、第三方 MCP provider、IdP 都有機會依同一規格支援。
  • 身份治理會成為 AI 工作力的集中控制層，而不是事後補上的安全措施。

企業導入提醒

  • 先盤點哪些工具最需要被 Claude 存取，以及哪些群組可以使用。
  • 不要只看「能不能連」，要把撤權、稽核、個人帳號隔離與 token 壽命納入設計。
  • 從 Team / Enterprise 方案與支援的 IdP／Connector 開始驗證，再逐步擴大。

原文整理

MCP在多人企業很實用，但大量多人授權一直都是非常麻煩的問題，Anthropic 推出 MCP Connector 企業集中授權：管理員設定一次，2,000 人零步驟上線，MCP Connector 的 Enterprise 集中授權正式上線（GA） 這次更新在做什麼：Anthropic 宣布 MCP Connector 的 Enterprise-managed auth（企業集中授權）功能正式 GA。這個功能針對 Claude Team 和 Enterprise 方案的管理員，讓他們可以透過組織現有的身份驗證提供商（IdP）集中管理 MCP Connector 的授權，使用者登入後就自動連好所有工具，不需要自己一個一個跑 OAuth 授權流程。 之前的流程 vs. 現在的流程：過去需要管理員在組織層級啟用 Connector，然後每個使用者自己做一次 OAuth 授權；Enterprise-managed auth 把第二步拿掉，管理員在 IdP 裡授權一次，使用者透過既有群組和角色繼承存取權限，第一次打開 Claude 時 Connector 就已經連好。 技術架構怎麼運作：管理員把組織 IdP 連上 Claude，選擇要啟用哪些 MCP Connector。員工登入後，Connector 已經到位。存取權限在 Claude Chat、Claude Code 和 Cowork 三個介面之間一致。管理員可以在 IdP 裡設定一次、按群組劃分權限、透過 IdP 處理撤銷，也可以縮短 access token 有效期，讓取消權限後的 Connector 存取快速過期。管理員還可以設定 Connector 只能透過 IdP 連線，乾淨分開工作帳號與個人帳號。 建立在開放標準上：Enterprise-managed auth 是 Model Context Protocol 的 Enterprise-Managed Authorization extension 的實作方向。任何 Connector 都可以支援，包括企業內部團隊自己建的 custom connector。 生態系合作夥伴：IdP 方面目前支援 Okta，後續會加入更多身份驗證提供商。MCP 提供商方面，GA 版本支援 Asana、Atlassian、Canva、Figma、Granola、Linear、Supabase、Slack、Datadog 和 Notion，Exa、Miro 和 Zoom 即將加入。Claude 企業客戶方面，HubSpot、Ramp 和 Webflow 是第一批在內部全面部署 enterprise-managed auth 的組織。 怎麼開始使用：Enterprise-managed auth 目前開放給 Claude Team 和 Enterprise 方案的客戶。Anthropic 在 Help Center 有詳細說明文件；身份驗證提供商或 MCP 提供商可透過實作 MCP 授權規格的開放 extension 支援 enterprise-managed auth。
