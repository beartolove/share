What'Sub 資安爭議解析｜Vibe Coding 新手上線前該注意什麼？

這支影片借 What'Sub 爭議提醒：Vibe Coding 可以快速做出產品雛形，但公開收費、保存使用者資料與正式上線後，資安、權限、成本與維運都必須被當成產品責任。

來源影片：https://www.youtube.com/watch?v=wYgKgIM4KT0
建立時間：2026-08-28（Asia/Taipei）

#科技及AI新知#VibeCoding#資安#產品上線#AIAgent

重點摘要

  • Vibe Coding 能快速做 demo，但公開收費產品要面對完全不同的責任。
  • What'Sub 的價值不只是自動字幕，而是字幕編輯、分段、音軌對齊、常用詞、金流與後台的完整工作流。
  • 產品開始收費並保存使用者資料後，就要處理機密性、完整性、可用性。
  • 瀏覽器看得到的資料就等於公開；真正要做的是後端不要送出不該給的資料。
  • 金流 HashKey、secret、API key 應放後端或環境變數，不應進入瀏覽器可下載層。
  • Supabase／Firebase 類工具要逐表檢查權限規則，不能只看正常操作是否成功。
  • 正式環境要關閉詳細錯誤，避免資料庫結構與檔案路徑外洩。
  • 上線後要準備流量、成本、用量上限、監控告警與維運支援。

影片中的例子

  • 上線兩天註冊破萬，帶來關注，也放大資安與可用性問題。
  • 有人一小時用 AI 做出相近功能，但影片提醒：能做出來不等於能產品化。
  • 影片留在使用者電腦，只抽音訊辨識，可兼顧部分隱私與伺服器成本。
  • F12 開發者工具能看到後端送到瀏覽器的資料，即使畫面沒有顯示。
  • 一般會員若可取得金流 HashKey，可能帶來交易破解或偽造付款通知風險。
  • 公開金鑰本身未必錯，真正要靠資料庫端權限規則保護資料。
  • 502 當機屬可用性問題；至少要有稍後再來頁面與通知機制。
  • 個人開發者出國時網站當機，可能仍要在飯店開筆電遠端處理。

上線前檢查清單

  • 先判斷是自己用作品，還是收費產品。
  • 敏感資料不送到瀏覽器。
  • 金鑰與 HashKey 放後端或環境變數。
  • 資料庫逐表檢查權限規則。
  • 正式環境關閉詳細錯誤。
  • 跑 AI 資安掃描，必要時找工程師複查。
  • 設定流量高峰備案、用量上限與成本通知。
  • 建立監控告警與維運支援。

一句話總結

Vibe Coding 讓做出來變容易，但把作品變成產品，靠的是資安、權限、可靠性、成本控制與有人負責維運。
