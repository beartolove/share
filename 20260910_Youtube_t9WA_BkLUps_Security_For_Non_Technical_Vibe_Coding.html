給非技術人員的資安教學｜Vibe Coding 必學的基本功

這支影片用 What'Sub 事件做案例，提醒非技術人員：AI 讓做產品變容易，但只要開始保存使用者資料、串金流或公開上線，就必須把資安、權限、成本與維運當成產品責任。

來源影片：https://youtu.be/t9WA-BkLUps?si=0XrSQ-pkldnhi1l8

重點摘要

  • Vibe Coding 可以把非技術人的想法快速變成產品，但「能動」不等於「能安全上線」。
  • 資安的核心不是背術語，而是確保系統被惡意操作時，仍能保護資料、金錢與服務可用性。
  • 上線前先盤點最重要資產：影片、逐字稿、帳號、金流、點數、API key 與管理後台。
  • Authentication 只確認身分；Authorization 才確認這個人是否有資格碰這筆資料或功能。
  • 資料從瀏覽器、後端、資料庫到外部 AI API 的每個交界，都是需要檢查的信任邊界。
  • 商業規則要放在後端與資料庫層守住，例如扣點、付款、用量限制與免費額度。
  • 攻擊面包含註冊、上傳、產生字幕、付款與 API 請求，每個入口都需要對應防禦。
  • Codex Security Plugin 可以協助掃描、修補與驗證，但產品責任仍要由開發者理解與承擔。

上線前檢查清單

  • 列出哪些資料或金鑰被偷會出大事。
  • 清楚定義訪客、免費使用者、付費使用者、管理員各自能做什麼。
  • 後端查資料時一定要檢查 owner / user_id，不要只確認「有登入」。
  • Supabase / Firebase 等資料庫要設定 Row Level Security 或等價隔離規則。
  • 扣點與付款流程要避免 Race Condition，不能先送昂貴任務、最後才扣點。
  • 高成本功能要有 Rate Limit、每日用量上限與帳單告警。
  • 檔案上傳要限制格式、大小、處理時間與儲存位置。
  • 每次改版後做 security diff scan，修補後要 verify fix。

風險提醒

  • 前端看不到不代表安全；只要資料已送到瀏覽器，就可能被開發者工具看見。
  • 金流 HashKey、secret、API key 不應進入瀏覽器可下載的前端程式碼。
  • 只做 Google 登入仍不夠；真正常出事的是登入後的資料授權檢查。
  • AI 可以幫忙掃漏洞，但不應取代人對金流、隱私與產品責任的判斷。

一句話總結

Vibe Coding 讓「做出來」變簡單，但「安全地交給別人使用」仍需要資產盤點、權限設計、信任邊界、商業規則與攻擊面檢查。
