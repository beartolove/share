重點摘要

Hooks 是 Claude Code 在指定事件發生時執行的「確定性自動門」：把不能依賴模型記憶的規則，變成可強制、可重複的工程流程。

  1. Hooks 與 CLAUDE.md 的分工不同：CLAUDE.md 是模型參考的專案規範；Hooks 由系統在事件點直接介入。一次性任務可在對話中說明，通用準則放入 CLAUDE.md，絕對不可漏做的動作才適合做成 Hook。
  2. 設定核心分成三層：event 決定何時啟動、matcher 篩選哪些工具或操作觸發、handler 定義實際執行的指令或流程。
  3. 先掌握常用事件，不必死背 31 個：從工具呼叫前攔截、工具完成後檢查、工作停止時收尾，以及使用者送出訊息時的前置處理開始。
  4. 將工程護欄自動化：例如修改程式後自動測試、危險 Git 指令先停下確認、提交前檢查格式或敏感資訊，降低 Agent 高速操作時的風險。
  5. 漸進導入：先挑一個最常重複、最不能遺漏的流程建立 Hook，確認觸發時機、輸出與副作用，再擴充為團隊規範。

何時應使用 Hook？

  • 規則必須每次執行，不能只靠模型「記得」。
  • 可明確定義觸發事件、篩選條件與處理指令。
  • 失敗時要有可理解的訊息與人工接手機制。
  • 先在低風險專案驗證，再推廣到團隊。
