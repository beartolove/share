重點摘要

這支影片的核心是把人與 AI 的協作默契分層管理：以 CLAUDE.md 保存長期協作規則、以 Skills 封裝重複工作流程，並只在可驗證且不能漏掉的場景使用 Hooks。先請 Agent 解釋與評估現有 starter kit，再依自己的工作方式個人化，避免不加選擇地安裝通用規則。

三層分工：何時用哪一種？

  • CLAUDE.md：每輪都會讀的協作基準；放背景、偏好、原則與必要限制。
  • Skill：把重複、具明確步驟的任務打包；需要時呼叫或自動匹配。
  • Hook：程式碼層級的強制閘門；放「絕對不能漏」且可驗證的條件。

影片介紹的 Skills 全清單

  1. ASD-STE100 Skill：將難懂、含糊的英文改成簡明技術英語。
  2. ISO 24495 Skill：用平實語言改寫，支援正體中文，重視讀者找得到、看得懂、用得上。
  3. Express Skill：以高中生也能理解的方式重講；先講結論、短句、類比、避免資訊堆疊。
  4. Polite Skill：對外文件或信件固定禮貌與商務語氣，可選不同溝通風格。
  5. 收工 Skill：盤點工作、寫日誌、執行 git commit／push，並回報收尾結果。
  6. Nit Freak：檢查多檔案或資料夾的事實是否同步，降低過期資料誤導 Agent 的風險。
  7. 第一性原理決策 Skill：先刪除不必要需求、挖掘本質、挑戰假設、辨識事實，再重組判斷。
  8. Info Diet：回顧讀過的網站與文章，檢視資訊來源是否偏頗或失衡。
  9. Phantom Pushback：減少模型未被要求時的說教、稻草人反駁與過度提醒。
  10. 分輪審閱與收斂 Skill：以段落 ID 追蹤修改、提問、討論與核准，避免長文件多輪審閱遺漏。（原稿未能可靠辨識其原始專名，故採功能名稱。）

Hooks 的 4 個落地情境

  1. 危險 Git 指令攔截：在 PreToolUse 檢查並阻擋高風險命令。
  2. 完成宣稱驗證：模型說「已驗證／已測試」時，確認是否真的執行對應工具。
  3. 找不到／無證據宣稱驗證：下結論前，確認是否真的有搜尋或查核。
  4. 寫檔品質檢查：偵測 emoji、UI 圖片、空連結、可讀性等不符合規則的產出。

提醒：安裝第三方 Skill 前，先閱讀其指令、腳本與權限；Skill 可能以你的權限執行，應視為供應鏈依賴。

開始方式

  1. 把 starter kit 連結交給 Agent，先請它用白話說明每個元件。
  2. 不要直接全裝；先討論哪些做法符合自己的工作型態。
  3. 把可彈性處理的規則留在 CLAUDE.md／Skill；將不可遺漏的要求改成可驗證 Hook。
