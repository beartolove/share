EmbeddingGemma 2：一個模型理解多種資料

文字、圖片、聲音、影片，都能放進同一個向量空間搜尋。

重點摘要

  • 用共同向量空間理解文字、圖片、音訊與影片，支援跨模態檢索。
  • 依需求載入模組，探索筆電與端側裝置上的本機搜尋。
  • 768 維向量可縮減；256 維的品質與成本取捨仍需依資料驗證。
  • 附件所述小型測試呈現良好效果，但不能直接外推企業環境。
  • 結合生成模型，有機會形成多模態 RAG 與 Agent 的本機檢索層。

本頁依熊熊提供的兩支影片整合筆記與附件整理。模型規格、示範能力及測試數字為附件轉述，未於本次重新實測或獨立查證；小型乾淨資料集的結果不代表企業資料效能保證。

完整內容｜9 頁簡報規劃

我已把兩份逐字稿整合，主軸聚焦在 EmbeddingGemma 2 是什麼、為什麼重要、可做什麼，以及實測效果與企業應用價值。以下規劃成 9 頁簡報，適合下一步直接做成 16:9 圖片簡報。

第 1 頁｜EmbeddingGemma 2：一個模型理解多種資料

一句話：文字、圖片、聲音、影片，都能放進同一個向量空間搜尋

  • Google 推出輕量級、開放的多模態 Embedding 模型
  • 支援：
    • 文字 Text
    • 圖片 Image
    • 音訊 Audio
    • 影片 Video
  • 不需要每種資料各自準備一套 Embedding 模型
  • 不同模態之間，可以直接比較「語意相似度」

視覺重點：
中央放 EmbeddingGemma 2，四周由「文字、圖片、聲音、影片」匯入同一個向量空間。

第 2 頁｜過去的問題：每種資料都要一套模型

一句話：傳統跨模態搜尋，系統架構複雜、模型也很多

傳統作法

  • 文字 → Text Embedding Model
  • 圖片 → Vision Model
  • 聲音 → Audio Model
  • 影片 → Video / Vision Model
  • 不同模型輸出的向量空間未必能直接比較

EmbeddingGemma 2

只需要：

一個模型 → 一個共同 Embedding Space

例如：

  • 「貓」這個文字
  • 一張貓的照片
  • 貓叫的聲音

都會被放到彼此接近的位置。

視覺重點：
左邊「4 種資料 → 4 套模型」，右邊「4 種資料 → EmbeddingGemma 2 → 同一空間」。

第 3 頁｜核心突破：跨模態可以直接搜尋

一句話：搜尋條件和搜尋結果，不需要是同一種資料

EmbeddingGemma 2 可以支援：

  • 文字 → 找圖片
  • 文字 → 找影片
  • 文字 → 找音訊
  • 音訊 → 找圖片
  • 影片 → 找圖片
  • 不同資料混合搜尋

例如輸入：

「一張馬的照片」

可以同時找出：

  • 馬的照片
  • 談論馬的語音
  • 出現馬的影片

核心能力

不同媒體格式 → 相同語意 → 相近向量

第 4 頁｜模型不大：最高約 7.4 億參數

一句話：它的重要特色不是只有多模態，而是能在端側設備執行

模型最高約：

740M parameters

逐字稿提到模組包含：

  • 約 270M：文字模型
  • 約 170M：視覺 Encoder
  • 約 300M：音訊 Encoder

而且可以依需求只載入需要的部分。

例如：

  • 只有文字搜尋 → 不載入影像、音訊
  • 圖文搜尋 → 只載入文字＋影像
  • 完整多模態 → 全部載入

意義：

不一定需要大型 GPU 或雲端服務，筆電、手機等 Edge Device 也有機會執行。

第 5 頁｜一個共同的 768 維向量空間

一句話：不同資料最後都轉成可直接比較的數字座標

官方介紹：

768 dimensions

而且使用 Matryoshka Representation Learning，可以縮減為：

  • 768
  • 512
  • 256
  • 128 dimensions

好處

向量越小：

  • 儲存空間越少
  • Vector Database 越省
  • 搜尋速度可能更快

實測中：

  • 768 維：表現佳
  • 256 維：仍維持相同的 Top-8 95% Precision
  • 儲存量僅約 1/3
  • 128 維開始出現較明顯下降

簡報可強調：

256 維可能是「品質 × 儲存成本」的甜蜜點，但仍須依實際資料驗證。

第 6 頁｜實測：8GB GPU 筆電就能跑

一句話：完整多模態模型實測約占 1.5GB VRAM

實測環境：

RTX 4060／8GB GPU Laptop

約使用：

模式 VRAM
只有文字 351 MB
文字＋圖片 899 MB
文字＋音訊 1,163 MB
完整模型 約 1,510 MB

模型載入時間約：

13～16 秒

因此即使完整模型：

約 1.5GB VRAM，仍遠低於 8GB GPU 的容量。

代表意義

Embedding 不一定只能放在：

Cloud

也可能移往：

Laptop / Phone / Edge Device

第 7 頁｜跨模態搜尋實測效果

一句話：小型測試中，文字、圖片、聲音與影片已能互相搜尋

測試資料：

  • 80 張圖片
  • 20 段音訊
  • 10 段影片
  • 10 種物件類別

測試結果

圖片搜尋

  • 10 種類別 Top-1：10 / 10 正確
  • Top-8 Precision：約 95%

文字 → 音訊

  • 10 / 10 正確

音訊 → 圖片

  • 20 / 20 正確

文字 → 影片

  • 10 / 10 正確

影片 → 圖片

  • 10 / 10 正確

但逐字稿也特別提醒：

這些是小型、相對乾淨的測試資料，不能直接等同真實企業環境。

第 8 頁｜更重要的是：資料可以不離開設備

一句話：Embedding 與搜尋可以完全在本機完成

Google 展示的應用包含：

Instant Media Search

直接使用自然語言找：

  • 照片
  • 圖片素材

Video Moment Finder

例如輸入：

「吹生日蠟燭」

直接找到影片中對應的時間片段。

而且：

  • 不需要先轉錄成文字
  • 不需要呼叫外部 API
  • 可以完全 Offline
  • 資料可以保留在本機

這使它特別適合

  • 隱私資料
  • 企業內部資料
  • 機敏檔案
  • 本地端 AI

第 9 頁｜從搜尋模型，進一步變成本地 RAG 與 Agent 基礎

一句話：EmbeddingGemma 2 的真正價值，是讓「所有企業資料」都有機會進入同一個 AI 檢索層

搭配輕量生成模型，可以形成：

本地資料
↓
EmbeddingGemma 2
↓
跨模態 Vector Search
↓
RAG
↓
LLM / Agent

未來 Agent 可以同時找：

  • Word / PDF 檔案
  • 圖片
  • 系統架構圖
  • 會議錄音
  • 教學影片
  • 現場照片

Google 示範甚至可以：

持續聆聽音訊 → 辨識問題 → 搜尋本機資料 → 找到相關架構圖 → 由生成式模型整理答案

最值得注意的轉變

過去：

RAG ≈ 找文字

未來可能變成：

RAG = 搜尋整個企業的多媒體知識
